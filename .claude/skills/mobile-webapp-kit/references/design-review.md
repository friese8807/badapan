# 디자인 변경 루틴 — 시안 3개 이상 → 선택 → 적용

**화면 모양이 달라지는 작업은 배포하기 전에 반드시 이 순서를 따른다.** 사용자가 정한 규칙이다.
한 가지 안을 바로 배포하고 "어떠세요?"라고 묻지 않는다. 휴대폰에 이미 반영된 뒤에 되돌리는 일을 없애기 위해서다.

## 해당하는 작업

- 새 앱의 첫 화면, 새 화면·탭·시트 추가
- 배치·색·글꼴·카드 모양·아이콘(홈 화면 아이콘 포함)·위젯 모양 변경
- "예쁘게", "보기 좋게", "깔끔하게", "디자인 바꿔줘" 같은 요청
- 기능 추가라도 화면에 새 요소가 눈에 띄게 생기는 경우(새 버튼 줄, 새 요약 칸 등)

## 해당하지 않는 작업 (바로 진행)

- 화면 모양이 그대로인 고장 수리·문구 오타·계산 수정·서버 쪽 변경
- 사용자가 모양을 정확히 지정한 경우("이 버튼을 빨간색으로", "글자 2px 키워줘")
- 이 스킬의 공통 처리 적용(공백 제거, 로딩 표시 등)으로 모양이 정해져 있는 것
- 사용자가 "시안 없이 바로 해줘"라고 말한 경우 — 그 작업에 한해서만

애매하면 시안을 만든다.

## 순서

1. **시안 만들기 (3개 이상)** — 작업 폴더가 아닌 임시 폴더(스크래치패드)에 `sample-a.html`, `sample-b.html`, `sample-c.html`.
   - 현재 `index.html`을 복사해 바꾸려는 부분만 다르게 만든다. 실제 앱 코드·예시 데이터로 그려야 한다(그림 흉내 금지).
   - 세 안은 **방향이 달라야** 한다. 색만 조금 다른 세 개는 시안이 아니다. 예: A 지금 구조를 다듬은 안 / B 정보 배치를 바꾼 안 / C 과감하게 다른 안.
   - 바꾸지 않는 부분(탭바, 공통 처리, 기능)은 세 안 모두 그대로 둔다.
   - 홈 화면 아이콘이면 SVG 3개 이상을 512 PNG로 만들어 나란히 보여 준다. 위젯이면 크기별 모양을 HTML로 흉내 내어 보여 준다.
2. **찍기** — 아이폰 크기로 나란히 붙인 한 장을 만든다.
   ```bash
   python3 scripts/samples.py 출력폴더 sample-a.html sample-b.html sample-c.html --labels "A 다듬기,B 목록형,C 큰 숫자" --dark
   ```
   바뀌는 화면이 첫 화면이 아니면 그 화면이 보이는 상태로 열리게 한다(`#demo&tab=list` 등 또는 시안 안에서 시작 탭 지정).
3. **보여 주기** — `compare.png`(어두운 화면이 달라지면 `compare-dark.png`도)를 사용자에게 보낸다. 각 안에 한 줄 설명: 무엇이 다른지, 어떤 때 좋은지.
   추천이 있으면 하나를 추천하고 이유를 한 줄로. 지금 화면과 비교가 필요하면 "지금"도 함께 넣는다.
4. **기다리기** — 사용자가 고를 때까지 **`main`에 올리거나 배포하지 않는다.** Apps Script 배포, 위젯 본체 교체도 마찬가지다.
   - "B인데 색은 A처럼"처럼 섞어 고르면 그대로 합쳐 한 번 더 한 장으로 보여 주고 확인받는다.
   - 마음에 드는 것이 없다고 하면 무엇이 아쉬운지 묻고 새로 3개를 만든다.
5. **적용** — 고른 안만 실제 `index.html`에 넣는다. 고르지 않은 안의 코드는 남기지 않는다.
   체크리스트(SKILL.md)를 다시 확인하고 `bump_version.py` 후 배포한다.
6. **알리기** — 어떤 안을 적용했는지, 휴대폰에서 다시 열면 바뀐다는 것을 알린다.

## 시안을 만들 때

- 시안도 공통 처리(화면 꽉 채우기, 안전 영역, 입력칸 16px, 밝은·어두운 화면)를 지킨다. 고른 안을 그대로 옮길 수 있어야 한다.
- 실제로 쓰는 데이터 양으로 채운다(긴 이름, 큰 금액, 목록 10개 이상, 빈 상태).
- 사진 찍힌 화면은 브라우저 화면이다. 아이폰 홈 화면 앱에서 달라질 수 있는 부분(하단 띠, 상태바)은 그렇다고 알린다.
- 여러 화면이 함께 바뀌면 화면마다 따로 세 개씩 만들지 말고, 안마다 대표 화면 1~2개를 찍는다.

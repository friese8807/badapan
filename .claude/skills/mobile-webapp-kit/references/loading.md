# 로딩·진행 표시

Apps Script 응답은 1~3초 걸린다. 눌렀는데 아무 반응이 없으면 사용자가 다시 눌러 중복 기록이 생긴다. 세 가지 경우를 구분한다.

## 1. 첫 화면

```html
<div class="ak-boot"><div><img src="icon-180-v1.png" alt=""><p>불러오는 중…</p></div></div>
```
- `body` 맨 앞에 HTML로 넣어 JS가 실행되기 전부터 보이게 한다. 앱 아이콘이 천천히 숨 쉬듯 움직인다.
- 첫 데이터가 준비되면 `AppKit.bootDone()`. 저장해 둔 지난 데이터가 있으면 그것을 먼저 보여 주고 바로 걷는다.

## 2. 사용자가 누른 동작 (저장·기록·삭제)

```js
api = AppKit.wrap(api, action => action === 'refresh');   // 서버 호출 함수를 한 번 감싸면 끝
```
- 누른 지 1.5초 안에 시작된 요청만 표시한다: 화면 맨 위 진행 막대(즉시) + "잠깐만요, 처리 중이에요" 알약(0.35초 뒤) + 누른 버튼 스피너·비활성(`.is-busy`).
- 알약은 탭바 위에 뜨고, 시트가 열려 있으면 버튼을 가리지 않게 화면 위쪽으로 옮긴다.
- 문구·이모지는 앱에 맞춘다: `AppKit.setBusy({ label:'기록하는 중이에요', emoji:'🐕' })`.
- 직접 지정: `AppKit.track(promise, { el:'#save', label:'보내는 중…' })`.
- 끝나면 `AppKit.toast('저장했어요')`로 결과를 알린다. 실패도 토스트로 쉬운 말로.

## 3. 배경 새로고침

```js
AppKit.spin('#refresh', api('refresh'));
```
- 자동 새로고침·화면 복귀 시 갱신은 새로고침 아이콘만 돌린다. 막대·알약을 띄우지 않는다.
- 새로고침 중에 사용자가 입력하던 값을 지우지 않는다(입력 중이거나 시트가 열려 있으면 다시 그리지 않는다).

## 공통

- `prefers-reduced-motion`이면 움직임을 느리게 한다(이미 CSS에 있음).
- 화면 전체를 덮는 로딩 막은 첫 화면 외에는 쓰지 않는다.
